# 红果短剧 Quantumult X 去广告 · 部署教程

## 一、交付文件一览

| 文件 | 路径 | 作用 |
|------|------|------|
| 重写脚本 | `scripts/HongGuo_Ads.js` | 响应体去广告 / 激励字段处理 |
| 重写规则 | `rewrite/HongGuo_Ads.conf` | URL 拦截 + MitM hostname + 挂载脚本 |
| 分流规则 | `filter/HongGuo_Ads.list` | 广告域名直连 reject（可选） |
| 订阅示例 | `rewrite/订阅示例.txt` | `[rewrite_remote]` / `[filter_remote]` 写法 |

---

## 二、前置条件

1. iPhone / iPad，已安装 **Quantumult X** 正式版  
2. 已有可用节点或直连策略（去广告主要依赖 **重写 + MitM**，不依赖特定节点）  
3. 能安装并信任 Quantumult X **HTTPS 解密证书**

---

## 三、证书配置（MitM 必做）

1. 打开 Quantumult X → **风车（设置）** → **MitM**  
2. 点击 **生成证书** → **安装证书**（跳转系统描述文件）  
3. iOS：**设置 → 通用 → VPN 与设备管理** → 安装 Quantumult X 描述文件  
4. **设置 → 通用 → 关于本机 → 证书信任设置** → 开启对 Quantumult X 证书的完整信任  
5. 回到 Quantumult X，打开 **MitM** 开关，并开启 **解密**  

未信任证书时，重写无法改 HTTPS 响应体，去广告基本无效。

---

## 四、导入方式（任选其一）

### 方式 A：远程重写订阅（推荐）

1. 将本仓库上传到 GitHub / Gitee，或放到任意可访问的 HTTPS 静态托管  
2. 得到 `HongGuo_Ads.conf` 与 `HongGuo_Ads.js` 的 **raw 直链**  
3. 编辑 conf 内所有 `HongGuo_Ads.js`，替换为 js 的 raw 地址  
4. Quantumult X → **设置 → 重写 → 引用** → 右上角添加：

```text
https://你的域名或raw地址/rewrite/HongGuo_Ads.conf, tag=红果短剧-去广告, update-interval=86400, opt-parser=true, enabled=true
```

5. 打开该引用开关；确认 MitM 已开启（远程 conf 内已含 `hostname`）

### 方式 B：本地导入

1. 用电脑 / 文件 App，将 `HongGuo_Ads.js` 放入 iCloud 中的：  
   `Quantumult X / Scripts/`  
2. 将 `HongGuo_Ads.conf` 内容复制到配置文件的 `[rewrite_local]` 段（不要带文件头说明以外的冲突 hostname 重复行过多时可合并）  
3. 或：重写 → 添加 → 类型选 `script-response-body` / `reject` 等，按 conf 逐条填写  
4. MitM → 主机名 → 添加 conf 中的 `hostname` 列表  

### 方式 C：分流（可选增强）

在配置文件 `[filter_remote]` 增加：

```text
https://你的raw地址/filter/HongGuo_Ads.list, tag=红果短剧-广告域名, force-policy=reject, update-interval=86400, enabled=true
```

分流与重写可同时开；若播放异常，先关分流只保留重写排查。

---

## 五、开启生效步骤

1. 确认 **重写** 总开关开启，且「红果短剧-去广告」为 enabled  
2. 确认 **MitM** 开启且证书已信任  
3. **彻底划掉** 红果短剧 App（不要只回桌面）  
4. 系统设置中清除红果短剧缓存（若有），或卸载重装后再登录（广告素材常本地缓存）  
5. 重新打开 App，验证开屏、播放贴片、弹窗、信息流  

---

## 六、App 内辅助设置（建议一并关闭）

即使规则生效，也建议在红果内减少广告请求：

**我的 → 设置 → 关于红果 → 了解与管理广告推送**

- 关闭「程序化广告展示」  
- 关闭「个性化广告展示」  

系统设置中可关闭红果的「运动与健身 / 加速度传感器」（减少摇一摇跳转）、关闭通知（减少推送弹窗）。

---

## 七、验收对照（对应需求文档第 8 章）

| 验收项 | 预期 |
|--------|------|
| 开屏 | 无全屏广告，尽快进首页 |
| 播放 | 无前置/中插贴片、无悬浮弹窗 |
| 列表 | 无明显推广广告卡片 |
| 激励解锁 | 尽量无需完整观看激励视频（依赖接口字段，见故障排查） |
| 核心功能 | 播放、选集、缓存、登录正常 |
| 持久性 | 重启 App / 重启 Quantumult X 后仍生效 |

## 八、故障排查

### 1. 完全无效（开屏、贴片都在）

- 证书是否「信任」而非仅「安装」  
- MitM / 重写开关是否打开  
- conf 里脚本地址是否 404（远程 js 打不开则改包失败）  
- 是否被其它规则抢先 `reject` 导致脚本未执行  
- App 是否证书锁定（SSL Pinning）：若抓包工具也看不到 HTTPS 明文，则 MitM 类方案对本版本可能失效，需等社区更新或改用无障碍点击类工具辅助跳过  

### 2. 仍有部分广告残留

- 删 App 重装或清缓存后再测（开屏图常缓存）  
- 打开 `HongGuo_Ads.js` 顶部 `debug: true`，看通知是否命中接口  
- 用 Quantumult X **HTTPS 解密抓包**，把仍下发广告的 URL 发到 conf 中追加 `reject-dict` 或交给脚本清洗  
- 在 `AD_KEYS` / `FEED_AD_MARKERS` 中补充新字段名  

### 3. 刷视频提示「网络错误，请点击重试」

- **原因**：旧版规则对 `*.fqnovel.com` 做了 MitM/改包，或匹配到含 `feed` 的业务接口  
- **处理**：已改为安全版——只拦穿山甲与广告素材；请更新远程重写后，在圈X里对该订阅点「更新」  
- 更新后：**划掉红果短剧** → 关开一次 Quantumult X → 再进 App  
- 若仍报错：暂时关闭本重写与对应分流，确认能刷后再只开重写；确认 MitM 主机名里没有手动加过 `*.fqnovel.com`  
- 不要对 `*.fqnovelvod.com` / `*.fqnovel.com` 做 reject 或全量改包

### 4. 能播但列表空白 / 页面错乱

- 关闭分流 `HongGuo_Ads.list` 再试  
- 不要对 `*.fqnovelvod.com` 做 reject（会断流）  

### 5. 激励解锁卡住、无法继续追剧

- 红果部分解锁强依赖服务端校验广告凭证，纯客户端改包可能不够  
- 可尝试：先正常看一次激励再观察请求；将「解锁成功」响应结构对照后扩展 `unlockRewardHints`  
- 临时方案：App 内「基本功能模式」（隐私政策路径，会退出登录、功能受限）或无障碍自动上滑跳过  

### 6. 登录失败 / 验证码异常

- 临时关闭对本 App 相关 hostname 的 MitM  
- 检查是否误杀 `security.snssdk.com`、`tnc*.zijieapi.com`（本规则默认不在分流里全禁 zijieapi）  

### 7. 规则升级后失效

- 每日自动更新：订阅 `update-interval=86400`  
- App 大版本更新后重新抓包，优先改 **正则通用段**（`/api/ad/`、`pangolin`、`ad-app-package`），再补业务字段  

---

## 九、安全与使用说明

- 本规则仅建议在自有设备、自用账号环境下使用  
- MitM 会解密指定域名流量，请勿在不信任的网络环境随意扩大 `hostname = *`  
- 不收集账号密码；脚本只在本地改写响应体  
- 字节系 App 更新频繁，无法保证永久 100% 去净，需保留迭代空间
